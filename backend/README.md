# lanka-api — бекенд «Ланка-Гіда»

Тонкий проксі між фронтендом `lanka` і Gemini API. Ключ тримається тут, у секреті кластера, а не в браузері. Без залежностей: Node 24 запускає `.ts` напряму.

- `POST /guide` — `{ "work": "<файл картини>", "messages": [{ "role": "user"|"guide", "text": "…" }] }`, відповідь потоком SSE: `data: {"text":"…"}` і наприкінці `data: {"done":true}`.
- `GET /health`.

Факти про твір сервер бере зі своєї копії `data/works.json`, а не від клієнта. Після зміни слайдів чи описів у `lanka` онови її: `npm run sync-data`.

У цьому репозиторії бекенд знаходиться в `backend/`, а фронтенд — у корені. Каталог синхронізований із 27 репродукціями фронтенду, включно з картиною дня та іншими епохами. Для авангарду передається контекст текстових слайдів; для інших епох — лише наявні дані про твір і назва його епохи.

## Для журі

- [src/server.ts](src/server.ts) — HTTP API, валідація, CORS, тайм-аут і передавання відповіді.
- [src/gemini.ts](src/gemini.ts) — реальний виклик Google Gemini через `streamGenerateContent`, читання SSE.
- [src/prompt.ts](src/prompt.ts) — системна інструкція: українська мова, 2–4 речення, лише надані матеріали, визнання відсутніх відомостей.
- [data/works.json](data/works.json) — матеріали про твори та епохи.
- [src/limits.ts](src/limits.ts) — обмеження частоти запитів.
- [test/server.test.ts](test/server.test.ts) — перевірки через підставний Gemini без платних викликів.

Модель не донавчається: сервер додає матеріали про твір і епоху до системної інструкції та передає історію діалогу. API-ключ береться зі змінної середовища `GEMINI_API_KEY` й надсилається Google у заголовку `x-goog-api-key`. У репозиторії ключа немає.

## Локальна перевірка на Windows

Потрібен Node.js 24. Залежностей немає, `npm install` не потрібен.

```powershell
cd backend
npm.cmd test
Copy-Item .env.example .env
# Заповни GEMINI_API_KEY у локальному .env (цей файл виключений із Git).
node --env-file=.env src/server.ts
```

Без API-ключа працює `GET http://localhost:8080/health`; `/guide` повертає 503, і фронтенд використовує локальну відповідь. Для роботи фронтенду з локальним сервером задай `VITE_GUIDE_API_URL=http://localhost:8080` у кореневому `.env.local` та перезапусти Vite.

Назва моделі в таблиці нижче — значення за замовчуванням у наданому коді, яке можна перевизначити через `GEMINI_MODEL`. Реальний доступ до неї перевіряється окремо командою `node --env-file=.env scripts/check-gemini.ts`; вона звертається до Google з вашим ключем. Під час публікації виконано лише тести з підставним Gemini.

`values.yaml` збережено як приклад конфігурації початкового Kubernetes-розгортання автора; він не запускає деплой із цього репозиторію. Публікація коду на GitHub сама по собі не змінює працюючий сервер.

## Налаштування (змінні середовища)

| Змінна | За замовчуванням |
|---|---|
| `GEMINI_API_KEY` | — (без нього `/guide` відповідає 503) |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` |
| `GEMINI_THINKING` | `MINIMAL` (порожнє — не передавати) |
| `ALLOWED_ORIGINS` | `https://lanka.nickromant.com` і localhost 5173/4173 |
| `RATE_PER_MIN` / `RATE_PER_DAY` / `GLOBAL_PER_DAY` | 15 / 200 / 3000 (в пам'яті процесу) |
| `MAX_OUTPUT_TOKENS` | 400 |

Тексти запитань не логуються, лише твір, статус і час.

## Запуск

```bash
GEMINI_API_KEY=… npm run check   # живий виклик: перевіряє ключ і модель
GEMINI_API_KEY=… npm start       # сервер на :8080
npm test                         # тести на підставному Gemini
```
